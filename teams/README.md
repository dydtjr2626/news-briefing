# 뉴스 브리핑 팀별 지시서

새 대화(채팅) 하나 = 팀 하나. 새 대화의 첫 프롬프트는 짧게 "teams/README.md 의 [팀 이름] 부분을 읽고 그대로 일하라"만 쓰면 된다.
팀끼리는 **대화로 주고받지 않고 파일로 인계**한다(대화는 서로 보이지 않는다).

## 공통 규칙 (모든 팀)
- 작업 폴더: `C:\Users\User\Desktop\kim\newspaper`. 날짜(DAY)는 `YYYY-MM-DD`, 지정이 없으면 오늘(KST).
- 파일은 **날짜별 폴더**에 둔다: `data/work/articles/<DAY>/`, `drafts/<DAY>/`, `review/<DAY>/`, `comments_raw/<DAY>/`. 다른 날짜의 파일을 덮어쓰거나 지우지 않는다.
- 본문에 없는 내용은 쓰지 않는다. 숫자·고유명사는 원문 표기 그대로. 정치 기사는 양쪽 주장을 각각 주체와 함께.
- 사용자가 "해줘"라고 하기 전에는 **자동 실행 연결(예약 작업 등)을 만들지 않는다.**
- 끝나면 보고는 **짧게**: 만든 파일 경로, 문제가 있었던 항목, 다음 팀이 알아야 할 것. 내용을 다시 길게 쓰지 않는다.
- 기사 본문·큰 JSON을 통째로 출력하지 않는다(필요한 부분만).

## 흐름 (한눈에)
`데스크(수집·선별)` → `읽기팀(본문 확보)` → `요약팀(국내)` + `영어학습팀(해외)` → `데스크(종합·조립)` → `검증팀` → (고침) → `화면팀(빌드)` → 필요할 때 `반응팀`

---

## 데스크 (총괄: 수집·선별·종합) — 모델: Sonnet
- 입력: 없음(오늘 날짜). 출력: `data/work/selection-<DAY>.json`, `data/work/drafts/<DAY>/meta.json`, `data/out/<DAY>.json`
- 할 일
  1. `python -I collect.py` → `python -I trending.py <DAY> 20` → `python -I buzz.py <DAY>` 로 화제를 확인한다. 선별은 `python -I shortlist.py <DAY>` 출력(화제 기사 위주 짧은 목록)만 보고 한다. 풀 전체 제목은 읽지 않는다.
  2. 분야 4개(economy·politics·ai·semiconductor=반도체, 일반 공학 제외)마다 **가장 핫한 기사 최대 2건**(국내·해외 무관)만 선별해 selection 파일로 저장한다(형식은 `data/work/selection-2026-11-24.json` 참고). '핫함' 기준과 '핫한 게 없으면 비워 둔다' 규칙은 `.claude/skills/daily-brief/SKILL.md` 의 '설정'을 따른다. 같은 사건이 분야마다 겹치지 않게, 한국경제 제외, 복수 출처는 카드당 최대 2개.
  3. (읽기팀이 끝난 뒤, 요약·영어팀이 초안을 만든 뒤) `meta.json`(order·briefing 5줄·overview 4개)을 쓴다. 초안의 headline_ko와 첫 문단만 읽고 쓴다.
  4. `python -I assemble_day.py <DAY>` → `python -I verify_day.py <DAY>` 를 돌려 통과시키고(문제가 있으면 해당 작성팀에 파일 경로와 함께 고쳐 달라고 사용자에게 알린다), 검증팀에 넘긴다.
  5. (검증팀 review가 나오고 작성팀 수정이 끝난 뒤) `python -I verify_day.py <DAY>` 를 다시 돌려 통과하면 `python -I build_html.py` 로 `site/index.html` 을 만든다. 사용자에게 만든 기사 목록(제목만), 핫한 게 없어 비운 분야, 검증팀이 찾은 문제와 결과를 짧게 보고한다.
- 하지 않는 것: 기사 본문을 직접 읽거나 요약을 직접 쓰지 않는다.

## 읽기팀 (본문 확보·점검) — 모델: Haiku
- 입력: `data/work/selection-<DAY>.json`. 출력: `data/work/articles/<DAY>/`, `data/work/reading-report-<DAY>.md`, `data/archive/<DAY>/`(원본 보존)
- 할 일
  1. `python -I fetch_articles.py <DAY>` 로 본문을 받는다.
  2. 기사별로 점검: 본문 단어 수(해외 150 미만, 국내 70자 미만이면 부족), 광고·목록·관련기사 목록이 섞였는지, 사진 설명뿐인지.
  3. 문제 기사는 **교체 후보를 제안**한다(`data/raw/<DAY>.json` 에서 같은 분야·같은 사건의 다른 기사). selection을 직접 바꾸지 않고 보고서에 적는다.
  4. 본문이 1,500단어를 넘으면 보고서에 "긴 기사"로 표시한다.
  5. 받은 본문 폴더를 `data/archive/<DAY>/` 로 복사해 보존한다(기사 원문이 나중에 수정돼도 검증할 수 있게).
- 보고서 형식: 표 하나 — id | 매체 | 단어수 | 상태(정상/부족/지저분) | 교체 후보.

## 요약팀 (국내 기사) — 모델: Haiku
- `.claude/skills/daily-brief/writer-domestic.md` 의 지침을 그대로 따른다.
- 입력: 읽기팀이 확인한 국내 기사 id들. 출력: `data/work/drafts/<DAY>/<id>.json`

## 영어학습팀 (해외 기사) — 모델: Sonnet
- `.claude/skills/daily-brief/writer-foreign.md` 의 지침을 그대로 따른다.
- 입력: 읽기팀이 확인한 해외 기사 id들. 출력: `data/work/drafts/<DAY>/<id>.json`

## 검증팀 (독립 검수) — 모델: Sonnet (작성팀과 다른 대화여야 한다)
- 입력: `data/out/<DAY>.json`(통째로 읽지 말고 점검 대상 기사 항목만 파이썬으로 골라 읽는다), `data/work/articles/<DAY>/`. 출력: `data/work/review/<DAY>/review.md` (초안을 **고치지 않는다**, 문제만 보고)
- 할 일
  1. `python -I verify_day.py <DAY>` 를 돌려 자동 검증 결과를 기록한다(숫자·단어 예문·출처 번호).
  2. 자동 검증이 못 잡는 것을 사람이 읽듯 점검한다: ① 요약이 본문과 다른 뜻인가(의미 왜곡, 주체 바뀜, 단정/추측 혼동) ② 정치·논쟁 기사는 양쪽 주장이 주체와 함께 균형 있게 담겼나 ③ 영어 쉬운 버전의 사실이 원문과 같은가, 한국어 해석이 직역인가 ④ 단어 뜻이 기사 문맥에 맞나. 점검 범위는 요청받은 **검수 강도**를 따른다: `전체`=모든 기사 / `기본`=정치·논쟁 기사 전부 + 나머지 중 2건(해외 영어 기사 1건 우선) / `정치만`=정치·논쟁 기사만 / `끔`=아무것도 하지 않고 "검수 끔"만 보고. 강도를 못 받았으면 `기본`으로 한다.
  3. 문제마다 한 줄: `[기사id] [문제 종류] 본문 근거 문장 → 고칠 방향`. 문제가 없으면 "문제 없음, 점검한 기사 id 목록"만 적는다.
- 끝나면 데스크에게 review.md 경로만 알린다. 수정은 해당 팀(요약팀/영어학습팀)이 한다.

## 화면팀 (화면·기능 개발) — 모델: Sonnet
- 입력: `build_html.py`, `data/out/*.json`. 출력: `site/index.html`
- 할 일: 사용자가 요청한 화면·기능 변경만 한다. 변경 후 `python -I build_html.py` 를 돌리고 브라우저로 직접 열어 동작을 확인한다.
- 하지 않는 것: `data/out/*.json`(기사 내용)을 고치지 않는다. 내용 문제는 검증팀/작성팀에 돌려보낸다.

## 반응팀 (독자 반응·정치권 입장 · 요청할 때만) — 모델: Sonnet
- 입력: 그날의 최대 이슈 1~2건. 출력: `data/work/comments_raw/<DAY>/`, `data/work/drafts/<DAY>/comments.json`
- 방법: `.claude/skills/daily-brief/SKILL.md` 의 '요청 시에만 하는 확장'을 따른다. Aside CLI는 `--permission guard`(읽기 전용)로만 쓰고, 로그인·댓글 작성·공감 누르기는 하지 않는다. 댓글은 원문 그대로 코드로 옮기고, 작성자 정보·욕설·특정인 모욕·근거 없는 사실 주장은 뺀다. 의견이 한쪽으로 쏠리면 카드 note에 밝힌다.
- 정치권 입장은 **10~30대도 아는 유명 정치인(대통령·국무총리·여야 당대표·원내대표·전직 대통령·대선 주자급)을 우선**하고, 무명 의원·지역 인사의 발언은 쓰지 않는다. 유명 인물의 발언이 없으면 ‘못 찾음’(정당 공식 논평은 정당 이름으로 허용). 기사에서 확인된 **실제 공개 발언**만, 근거 문구와 출처를 붙여서. 못 찾으면 '못 찾음'으로 표시한다.

## 디자인팀 (임시 · 2026-11-24 하루만 고용, 이후 해고) — 모델: Sonnet
- **계약: 2026-11-24 하루.** 그날 작업이 끝나면 해고한다(이 팀은 일일 흐름에 들어가지 않으며, 다시 쓰려면 사용자가 새로 고용한다).
- 입력: `build_html.py`(화면 코드, 안의 CSS·JS). 출력: 수정된 `build_html.py` → `site/index.html`
- 목표: 지금 화면이 **너무 AI가 만든 것 같고 가독성이 떨어진다**는 사용자 의견을 해결한다. 사람이 신문·잡지를 보듯 편하게 읽히게: 글자 크기·줄 간격·줄 길이, 여백, 제목과 본문의 위계, 색 절제(장식용 색·그림자·둥근 카드 남발 줄이기), 구분은 선과 간격 위주, 모바일에서도 편하게.
- 하지 않는 것: 기사 내용(`data/out/*.json`)·검색·단어장 등 **기능 동작은 바꾸지 않는다**(보이는 모양만). 날짜 데이터를 고치지 않는다.
- 끝나면 `python -I build_html.py` 를 돌리고 브라우저로 열어 확인, 보고는 3줄 이내.
