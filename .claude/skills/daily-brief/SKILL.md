# 일일 브리핑 (가벼운 방식)

**새 대화에서 실행한다.** 긴 대화는 매 동작마다 앞 내용을 다시 읽어 비용이 크다. 이 세션은 **지휘만** 한다(선별·종합·검증 확인). 기사 본문 읽기와 글쓰기는 **하위 에이전트**에게 맡긴다. 이 세션이 기사 본문을 직접 읽지 않는다.

작업 폴더: `C:\Users\User\Desktop\kim\newspaper`. 날짜 인자가 없으면 오늘(KST).

## 설정 (바꾸려면 여기만 수정)
- **HOT_MAX_PER_CATEGORY = 2**: 분야 4개(economy·politics·ai·semiconductor)마다 **가장 핫한 기사 최대 2건**. 국내·해외를 가리지 않고 핫한 순서로 고른다.
- **반도체 분야(2026-11-24 변경, 옛 '공학 기술' 대체)**: 일반 공학(로봇·건설·에너지 등)은 **제외**하고 반도체만 다룬다. 반도체 기술·기업(삼성·SK하이닉스·TSMC·엔비디아·인텔 등)·시장·정책·일자리·채용 등 **반도체에 관한 화제면 무엇이든** 대상이다. 수집 시 `sources.json` 의 keywords 로 반도체 기사만 풀에 들어온다.
- **핫함 기준**: 한 사건이 아래 3개 중 **2개 이상**을 충족하면 '핫하다'.
  - (a) Google 뉴스(`buzz.py` 결과) 주요 또는 해당 분야 순위 **15위 안**
  - (b) 우리 기사 풀에서 같은 사건을 다룬 기사가 **3건 이상**(가능하면 매체 2곳 이상)
  - (c) `trending.py` 상위 20 단어에 그 사건의 핵심어가 있음
- **핫한 게 없으면 억지로 채우지 않는다.** 그 분야는 0건으로 두고 화면에 '오늘은 핫한 기사가 없습니다'가 나오게 한다. **1건만 핫하면 1건만** 만든다.
- **영어 학습 최소 보장 = 켬(2026-11-24 사용자 요청)**: 선별 결과에 해외 기사가 하루 전체에서 0건이면 영어 학습용으로 해외 기사 **1건을 추가**한다(2단계 참고). 끄려면 `끔`으로 바꾼다.
- **검수 강도 = 기본**: `전체`(모든 기사) / `기본`(정치·논쟁 기사 전부 + 나머지 중 2건, 해외 영어 기사 1건 우선) / `정치만` / `끔`(자동 검증만, 검증팀 생략)
- 해외 기사는 영어 학습 풀 버전(쉬운 영어·해석·단어 12개·질문), 복수 출처는 카드당 **최대 2개**
- 독자 반응(댓글)·정치권 입장은 **요청할 때만** 만든다(비용이 큼)

## 지킬 것
- 사용자가 "해줘"라고 하기 전에는 **자동 실행 연결(예약 작업 등)을 만들지 않는다.**
- 본문에 없는 내용은 쓰지 않는다. 정치 기사는 양쪽 주장을 각각 주체와 함께 쓴다.
- 날짜별 폴더를 쓴다(`data/work/articles/<날짜>/`, `drafts/<날짜>/`). 다른 날짜 파일을 덮어쓰지 않는다.
- 한국경제(hankyung) 기사는 본문 추출이 안 되므로 선별에서 제외한다.

## 순서
1. **수집·화제** (명령어 3개, 출력은 짧게 확인)
   `python -I collect.py` → `python -I trending.py <날짜> 20` → `python -I buzz.py <날짜>` → `python -I shortlist.py <날짜>`
   - **선별은 `shortlist.py` 출력만 보고 한다**(반도체는 전부, 나머지 분야는 Google 뉴스 화제와 매칭된 기사만). 수집 풀 전체 제목(경제·정치만 수백 건)을 읽지 않는다. 후보가 모자라면 `python -I shortlist.py <날짜> --all <분야>` 로 그 분야만 전체를 본다.
2. **선별(핫한 것만)**: 화제 결과에서 핫함 기준을 충족하는 사건을 찾아 분야별로 묶고, 분야마다 핫한 순서로 최대 2건을 고른다. `data/work/selection-<날짜>.json` 으로 저장한다.
   - 형식은 `data/work/selection-2026-11-24.json` 을 참고(id, category, region, outlet, title, url, published, rss_summary, 선택적 extra[] = 추가 출처). id 규칙: `eco-d1`, `eco-f1`, `pol-d1`, `ai-d1`, `semi-d1`, `semi-f1` … (d=국내, f=해외)
   - 같은 사건이 여러 분야에 겹치지 않게 한다. 대표 기사는 본문 추출이 되는 매체(연합뉴스·전자신문·ZDNet·BBC·NPR 등)로 고른다.
   - 제목·RSS 요약만 보고 고른다(본문을 읽지 않는다).
   - 핫한 게 없는 분야는 selection에 넣지 않는다.
   - **영어 학습 최소 보장(켬)**: 위로 고른 결과에 해외 기사가 0건이면, 해외 기사 풀에서 **화제 점수가 가장 높은 기사 1건**을 영어 학습용으로 추가한다. 국내 카드와 같은 사건이어도 된다(영어 읽기가 목적이므로). 단, 본문이 영어 문장으로 이루어진 일반 기사(약 300~1,000단어)를 고르고, 인터뷰·팟캐스트 대본, 여러 소식이 섞인 뉴스레터, 목록형 페이지는 피한다. 분야는 기사 성격에 맞게 정한다. 이 경우 그 분야가 1건 늘어나므로 분야당 2건 한도는 넘지 않게 한다.
   - 이미 `selection-<날짜>.json` 이 있고 `data/work/articles/<날짜>/` 에 본문이 받아져 있으면(수집을 이미 한 날) 1~2를 건너뛰고, 그 파일에서 핫함 기준으로 줄이기만 한다.
3. **본문 확보**: `python -I fetch_articles.py <날짜>` → 출력의 단어 수를 보고 너무 짧거나(해외 150단어 미만, 국내 70자 미만) 실패한 기사는 같은 사건의 다른 기사로 바꾸고 3을 반복한다. 받은 본문 폴더를 `data/archive/<날짜>/` 로 복사해 둔다(원문이 나중에 수정돼도 검증할 수 있게).
4. **작성 위임** (한 메시지에서 Agent를 병렬로 호출)
   - 국내 기사: **`model: "haiku"`**, 지침 파일 `.claude/skills/daily-brief/writer-domestic.md`. 에이전트 1개가 국내 기사 4건까지 맡는다.
   - 해외 기사: **`model: "sonnet"`**, 지침 파일 `.claude/skills/daily-brief/writer-foreign.md`. 에이전트 1개가 해외 기사 2건까지 맡는다.
   - 프롬프트는 짧게: "지침 파일을 읽고, 날짜 <DAY>, 기사 id [ ... ] 에 대해 지침대로 초안을 저장하라."
   - 결과: `data/work/drafts/<날짜>/<id>.json`. 기사 수가 적으면 에이전트 수도 줄인다(기사 2~3건이면 1개로 충분).
5. **종합**: 이 세션이 `data/work/drafts/<날짜>/meta.json` 을 쓴다. 초안의 `headline_ko` 와 `summary_ko` 첫 문단만 읽고 작성한다.
   ```json
   {"order": {"economy": ["eco-d1", ...], "politics": [], "ai": [...], "semiconductor": [...]},
    "briefing": [{"text": "한두 문장", "refs": ["기사id"]}],
    "overview": {"economy": {"text": "분야 총평 한 문단", "refs": ["기사id", ...]}, "ai": {...}}}
   ```
   - 핫한 기사가 없는 분야는 `order` 에 빈 배열(`[]`)로 두고 `overview` 는 생략한다(조립 코드가 '오늘은 핫한 기사가 없습니다'로 채운다).
   - briefing 은 그날 가장 큰 사건 순서로 **최대 5줄**. 기사 수가 적으면 그만큼만(1~2건이면 1~2줄). 숫자는 해당 기사 초안에 있는 것만 쓴다.
6. **조립·자동 검증**: `python -I assemble_day.py <날짜>` → `python -I verify_day.py <날짜>`
   - 숫자·단어 예문·출처 번호 문제가 나오면 그 기사를 쓴 하위 에이전트에게 SendMessage로 “verify 결과: …를 고쳐라”라고 보낸다. 이 세션이 직접 고치지 않는다(한 줄짜리 오류 제외). 통과할 때까지 반복하되 **최대 2회**.
7. **독립 검수 (검증팀)**: 자동 검증이 못 잡는 **의미 왜곡**을 잡는 단계다. **검수 강도가 `끔`이면 건너뛴다.** 작성에 쓰지 않은 **새 하위 에이전트**(`model: "sonnet"`, 대화 맥락 없음)를 하나 띄운다.
   - 프롬프트: "`teams/README.md` 의 '공통 규칙'과 '검증팀' 부분을 읽고 그대로 일하라. 날짜 <날짜>. **검수 강도: <값>**. 초안은 고치지 말고 문제만 보고하라."
   - 산출물: `data/work/review/<날짜>/review.md` (기사별 `[기사id] [문제 종류] 근거 문장 → 고칠 방향`). 이 세션은 review.md 만 읽는다.
8. **수정 반영**: review.md 의 문제를 해당 기사의 하위 에이전트에게 SendMessage로 돌려 고치게 한 뒤 6의 자동 검증을 다시 돌린다. 수정은 **한 번만** 한다(그래도 남은 문제는 보고서에 한계로 적는다). 문제가 없으면 이 단계는 건너뛴다.
9. **화면**: `python -I build_html.py` → `site/index.html` 을 브라우저로 한 번 열어 확인한다.
10. 사용자에게: 만든 기사 목록(제목만), **핫한 기사가 없어 비워 둔 분야**, 검증팀이 찾은 문제와 고친 결과, 남은 한계를 짧게 알린다.

## 막혔을 때 팀장이 알아서 하는 규칙 (모델은 바꾸지 않는다)
사용자에게 되묻지 않고 아래 순서로 처리하고, 마지막 보고에 무엇을 했는지만 적는다. **더 센 모델로 교체하지 않는다**(각 하위 에이전트는 처음 정한 모델 그대로).
1. **자동 검증(verify_day) 실패**: 그 기사를 쓴 에이전트에게 SendMessage로 문제 목록을 주고 고치게 한다. 통과할 때까지 **최대 2회**.
2. **검증팀 review 문제**: 해당 에이전트에게 문제 목록을 주고 **1회** 고치게 한 뒤 자동 검증을 다시 돌린다.
3. **초안 파일이 없거나 JSON이 깨짐**: 같은 지침으로 **1회** 다시 맡긴다.
4. **본문이 부족해 쓸 수 없음**: 같은 사건의 다른 기사로 **1회** 교체한다. 대체할 기사가 없으면 그 기사를 뺀다.
5. **위 규칙으로도 통과하지 못한 기사**: 화면에 올리지 않고(`meta.json` 의 `order` 에서 뺀다) 마지막 보고에 사유를 적는다. 틀린 내용을 싣는 것보다 빼는 쪽을 택한다.

## 요청 시에만 하는 확장
- **독자 반응(댓글)**: Aside CLI(`aside --permission guard "<프롬프트>"`)로 네이버 검색 상위 기사에서 베스트 댓글을 수집한다. 원본 기록을 `data/work/comments_raw/<날짜>/<기사id>.txt` 에 저장하고, 댓글 텍스트는 코드로 읽어 `drafts/<날짜>/comments.json` 에 넣는다(직접 타이핑 금지). 작성자 정보·욕설·특정인 모욕·근거 없는 사실 주장은 제외한다. 의견 쏠림은 카드 note에 밝힌다.
- **정치권 입장 대댓글**: **10~30대도 아는 유명 정치인을 우선한다**(대통령·국무총리·여야 당대표·원내대표·전직 대통령·대선 주자급 인지도의 인물). 무명 의원·지역 인사의 발언은 쓰지 않는다. 그런 유명 인물이 이 쟁점에 실제로 한 발언이 없으면 지어내거나 인지도 낮은 인물로 채우지 말고 ‘못 찾음’으로 표시한다(정당 공식 논평은 정당 이름으로 허용). 이 쟁점에 대한 여당·야당의 실제 공개 발언만 근거 문구와 함께 붙인다(`data/work/statements/<날짜>/index.json` 형식). 못 찾으면 ‘못 찾음’으로 표시한다.
- 이 확장의 데이터 형식과 검증 규칙은 `verify_day.py` 와 `data/out/2026-11-19.json` 의 `comments`·`replies` 를 참고한다.

## 비용을 아끼는 습관
- (2026-11-24) 결과·과정은 그대로, 읽는 양만 줄인다: `collect.py` 는 반도체 기사만 풀에 넣고, `buzz.py` 는 우리 풀에 매칭된 화제만 출력한다. 명령 출력이 길면 `| head -60` 으로 자르고, 선별은 제목·RSS 요약만 본다. 하위 에이전트 보고는 3줄 이내. 검증팀은 `data/out/<날짜>.json` 을 통째로 읽지 말고 점검 대상 기사 항목만(파이썬으로 id 골라) 읽는다.
- 기사 본문, 큰 JSON을 이 세션에서 `cat`/Read로 통째로 출력하지 않는다. 필요한 부분만 본다.
- 하위 에이전트의 보고에 내용이 다시 길게 오지 않도록 지침에 이미 “내용은 보고하지 말 것”이 있다.
- 한 번에 끝낸다. 중간에 사용자에게 되묻지 않고 기본값으로 진행한 뒤 마지막에 보고한다.
